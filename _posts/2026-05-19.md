### 1. fstream
C++에서 파일 입출력 기능을 사용하기 위해서는 `<fstream>`헤더를 인클루드 하면 된다. 파일 입출력도 `<iostream>`처럼 입출력 스트림을 통하기 때문에 `ios_base`를 상속받은 클래스를 사용한다. 파일을 읽어 들이기 위해선 `ifstream`, 쓰기를 위해는 `ofstream`을 사용하는데, 각각 알아보자.
### 2. ifstream
파일 입력을 위해 쓰이는 클래스이다. 기본적인 사용 방법은 객체를 생성한 뒤, `open()`함수를 통해 스트림을 열어주면 된다. `open()`의 첫번째 인자는 파일의 이름을 받는데, 기본적으로 솔루션 위치 기준 상대경로를 받는다. 두번째 인자는 오픈모드인데, 기본은 `in`으로 되어 있으며 `ofstream`의 경우는 기본값이 `out`이다.
`open()`함수를 사용하지 않고 오버로딩된 생성자를 사용해도 된다. `open()`에 넣을 인자를 생성자에 그대로 넣게 되면 객체의 생성과 함께 스트림을 열 수 있다. 스트림이 잘 열렸는지 확인하고 싶다면 `isopen()`함수를 사용하면 된다.
열린 스트림을 통해 실제 내용을 읽는 방법은 여러 가지가 있는데, 먼저 `string`을 통해 줄 단위로 읽는 방법이다.
```cpp
std::ifstream testFile("test.txt", std::ios_base::in);

if (testFile.is_open()) {
	string str;
	while (std::getline(testFile, str)) {
		cout << str << endl;
	}
}
testFile.close();
```
`std::getline()`함수를 사용하며, 스트림과 `string`객체를 넣어주면 된다.
참고로 이것이 `std::getline()`은 `bool`값이 아니라 사용된 스트림을 그대로 반환하는데, 스트림은 연산자 오버로딩으로 `bool`로 형변환 될 수 있게 되어 있다. (EOF에 도달하면 `false`)
사용이 끝난 스트림은 반드시 닫아 주어야 한다. 열었다면 닫는 것 까지가 세트이다. (사실 까먹더라도 소멸자에서 해주긴 한다.)

```cpp
std::ifstream testFile("test.txt", std::ios_base::in);

if (testFile.is_open()) {
	char buf[100];
	while (!testFile.eof()) {
		testFile.getline(buf, 100);
		cout << buf << endl;
	}
}
testFile.close();
```
위와 같이 `char`배열로도 가능하다. 여기선 `eof()`함수를 사용했는데, 이는 End Of File의 약자로 파일의 끝에 도달했는지를 반환하는 함수이다.
외에도
```cpp
char c;
while (testFile.get(c)) {
	cout << c;
}
```
이렇게 문자 단위로 받는 것도 가능하다. 역시 `istream`을 반환하기에 `while`문에서 그대로 사용 가능하다.
`+ 참고로 cin과 비슷하게 testFile >> s도 가능하다.`
### 3. ofstream
`ofstream`역시 기본 사용 원리는 `ifstream`과 같다. `open()`을 통해 열고, `close()`를 통해 닫으면 된다. 파일에 특정 내용을 작성하고 싶다면 다음과 같이 하면 된다.
```cpp
std::ofstream testFile("test.txt", std::ios_base::out);

char arr[] = "와샌즈!아시는구나참고로겁나어렵습니다";
if (testFile.is_open()) {
	testFile.write(arr, strlen(arr));
}
testFile.close();
```
`write()`함수를 사용할 때에는 문자열의 길이도 함께 보내줘야 한다.
오픈모드가 `out`이면 기존의 내용을 덮어쓴다. 만약 뒤에 추가로 붙이고 싶다면 기존의 내용을 `ifstream`으로 읽어들인 후 함께 적어도 되지만, 너무 비효율적이다. 아니, 그러면 안 된다. 굉장히 나쁜 코드이다. 그럴 땐
```cpp
std::ofstream testFile("test.txt", std::ios_base::app);

char arr[] = "와샌즈!아시는구나참고로겁나어렵습니다";
if (testFile.is_open()) {
	testFile.write(arr, strlen(arr));
}
testFile.close();
```
오픈모드를 `app`으로 바꿔주면 된다. `app`은 append를 의미한다.
`ofstream`역시 `ifstream`과 마찬가지로 연산자 오버로딩을 해 두었기 때문에,
```cpp
testFile << "겜프야르";
testFile << "겜프야르";
testFile << "겜프야르";
testFile << endl;
testFile << endl;
testFile << endl;
testFile << 야호!;
```
이런 문법이 가능하다. 이쪽이 가독성 측면에서 더 좋을 것 같기도 하다.

### 1. 생성자
생성자는 객체의 생성을 담당하는 일종의 메서드 비슷한 친구이다.
난 클래스에서 생성자가 매우 중요하다고 생각한다. 생성자는 잘 활용한다면 단순히 초기화의 용도를 넘어 구조 자체를 정의하는 역할로써 쓰일 수 있다고 본다.
각설하고 시작하자면 C++에서 생성자는 다음과 같이 만든다.
```cpp
class Object {
public:
	Object() {}
}
```
클래스의 이름과 동일한 이름을 가진, 메서드 처럼 생겼다, 그러나 반환 형식은 없는.
생성자의 본문은 주로 객체의 초기화 로직을 작성한다. 예를 들자면 다음과 같다:
```cpp
class Object {
public:
	Object() {
		_hp = 20;
		_name = "Hello";
	}
private:
	int _hp;
	string _name;
}
```
또한 생성자는 매개변수를 받을 수 있다.
```cpp
class Object {
public:
	Object(int hp, string name) {
		_hp = hp;
		_name = name;
	}
private:
	int _hp;
	string _name;
}
```

```cpp
Object() {}
```
이렇게 본문이 없는 생성자는
```cpp
Object() = default;
```
이렇게 적을 수도 있다.
멤버 변수의 초기화는 본문에 적지 않고 다음과 같이 적을 수도 있다:
```cpp
class Object {
public:
	Object(int hp, string name)
		: _hp(hp)
		, _name(name)
	{	}
private:
	int _hp;
	string _name;
}
```
만약 다음과 같은 상황에선 `_hp`의 값이 어떻게 될까?
```cpp
class Object {
public:
	Object()
		: _hp(1)
	{
		_hp = 2;
	}
private:
	int _hp = 3;
}
```
답은 2가 된다. 항상 생성자의 본문이 마지막에 호출되고, 3, 1, 2 순이다.

생성자도 접근 제한자를 사용하는 것이 가능하기 때문에 `private`생성자로 외부에서의 객체 생성을 제한하는 등의 활용이 가능하다. 

### 2. 소멸자
소멸자는 생성자와 반대로 객체의 메모리상에서의 정리를 담당한다. 소멸자가 호출되는 경우는 다음과 같다.
- 객체가 스택에 할당된 코드블럭이 끝날 때
- 동적 할당 된 객체를 `delete`할 때
소멸자는 생성자의 앞에 ~를 붙인 모습이다.
```cpp
class Object {
public:
	~Object() {}
}
```
아무래도 매개변수는 받을 수 없다.
주로 소멸자의 본문 내에서는 멤버 객체 `delete`, 메모리 정리 로직 등이 들어간다.
C#의 소멸자는 GC가 호출해 주기 때문에 호출 시점이 불분명하다는 점이 있었는데, C++은 소멸자가 어디서 불릴 지 예상할 수 있기 때문에 그것이 참 좋은 것 같다.

### 3. 상속
클래스는 상속을 할 때 빛을 발한다. 클래스에 상속이란 개념이 없다면 그건 그냥 C언어의 구조체와 다를 게 없다.
상속은 클래스 이름 오른쪽에 `:`기호를 사용해 나타낸다.
```cpp
class Object {
public:
	void HelloWorld() {
		cout << "Hello, World!" << endl;
	}
}

class ObjectTwo : Object {
}
```
이제 됐겠지? 하고 `main`에서 호출해 본다면
```cpp
int main() {
	ObjectTwo o;
	o.HelloWorld(); // 에러
}
```
안된다.
방금 한 것은 `private`상속이기 때문이다.
`ObjectTwo : Object`는 사실 `ObjectTwo : private Object`를 의미한다.
`private`상속이란 특정 클래스의 멤버를 물려받되, 그 물려받은 멤버를 밖으로 노출하진 않는 것이다. 그렇다면 우리가 해야 할 일은 `public`키워드를 앞에 붙여주는 일 뿐이다.
```cpp
class Object {
public:
	void HelloWorld() {
		cout << "Hello, World!" << endl;
	}
}

class ObjectTwo : public Object {
}

int main() {
	ObjectTwo o;
	o.HelloWorld(); // 잘 됨.
}
```

### 4. 가상과 추상
상속을 하는 이유 중 가장 주된 이유는 아마 다형성 때문일 것이다. 이는 `virtual`과 `override`키워드를 통해 이루어진다.
```cpp
class Object {
public:
	virtual void HelloWorld() {
		cout << "Hello, World!" << endl;
	}
}

class ObjectTwo : public Object {
public:
	void HelloWorld() override {
		cout << "Not Hello, World!" << endl;
	}
}
```
이번엔 동적 할당으로 테스트 해 보겠다.
```cpp
int main() {
	Object* ptr = new ObjectTwo();
	ptr->HelloWorld();
}
```
이 프로그램은 `Not Hello, World!`를 출력한다. 이는 가상함수 테이블을 통해 이루어지는데, 우린 `Object`의 `HelloWorld()`를 호출했지만 실제 함수가 호출될 땐 `override`된 함수로 호출된다.

추상도 기본적으로 비슷하다. C#에선 `abstract`키워드로 추상 메서드를 선언했지만, C++은 좀 다르다.
```cpp
class Object {
public:
	virtual void HelloWorld() = 0;
}
```
굉장히 어색한 문법인데, 곧 익숙해질 것이다. 아마. 이를 순수 가상함수 (혹은 추상)이라 부르며, 이를 가진 클래스는 추상클래스로 취급된다. 또한 만약 클래스가 멤버 변수를 가지지 않고 순수 가상 함수만을 가지고 있다면 그것은 **인터페이스**가 된다.

### 5. 생성자, 소멸자와 상속
여기 `Object`와 그를 상속받은 `Enemy`가 있다.
```cpp
class Object {
public:
	Object() { cout << "Object 생성자" << endl; }
	~Object() { cout << "Object 소멸자" << endl; }
};

class Enemy : public Object {
public:
	Enemy() { cout << "Enemy 생성자" << endl; }
	~Enemy() { cout << "Enemy 소멸자" << endl; }
};
```
이런 코드를 써보자.
```cpp
int main() {
	Enemy e;
}
```
출력 순서를 예상해 보자.

답은
```
Object 생성자
Enemy 생성자
Enemy 소멸자
Object 소멸자
```
가 된다. 여기까진 어렵지 않게 예상이 된다.
그렇다면 다음의 경우는?
```cpp
int main() {
	Object* ptr = new Enemy();
	delete ptr;
}
```
답은
```
Object 생성자
Enemy 생성자
Object 소멸자
```
하나가 사라졌다. 이는 포인터를 `delete`할 때 `Object`의 소멸자만을 호출해주기 때문인데, 그렇다고 메모리 누수가 발생하진 않는다. 하지만 누수가 발생할 위험은 있는데, `Enemy`의 소멸자가 멤버 포인터를 정리해주는 경우 이를 호출하지 않아 발생하는 누수는 별개이다. 무엇보다 이런 상황 자체가 UB이기 때문에 피해야 할 것이다.
이럴 땐 소멸자를 `virtual`로 선언해주면 된다.
```cpp
class Object {
public:
	Object() { cout << "Object 생성자" << endl; }
	virtual ~Object() { cout << "Object 소멸자" << endl; }
};

class Enemy : public Object {
public:
	Enemy() { cout << "Enemy 생성자" << endl; }
	~Enemy() { cout << "Enemy 소멸자" << endl; }
};
```
이제 `Enemy`의 소멸자도 제대로 호출되는 것을 볼 수 있다.
